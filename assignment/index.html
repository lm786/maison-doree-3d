Introduction

For this assignment I created Maison Dorée, a fictional Parisian café presented as an interactive 3D menu. The idea came from wanting to build something that felt like a real product rather than just a technical demo. A café felt like a natural fit because it gave me three visually distinct objects to model including a croissant, a coffee cup, and a chocolate chip cookie, each with different shapes and materials that would showcase the 3D rendering well. The name Maison Dorée means "Golden House" in French, which tied into the warm gold colour scheme I had in mind from the start.

Creative & Design Decisions

I wanted the overall look to feel like a high-end café menu rather than a typical student web project, so I drew inspiration from editorial food photography and luxury brand websites. I chose a warm parchment colour palette using cream, gold, and deep espresso brown because these colours feel associated with quality food and French patisseries. For typography I picked Playfair Display, an elegant serif font for headings to reinforce the premium feel, and DM Mono for body text to give a clean modern contrast.

The layout uses a two-column CSS Grid with a narrow panel on the left for model selection and controls, and the 3D canvas taking up the larger right-hand area. This was a deliberate decision to keep the 3D model as the focal point of the page at all times. I added a scrolling ticker strip along the top inspired by news tickers and stock market displays, which adds movement and life to the page. All colours are stored in CSS custom properties so the entire palette can be adjusted from one place.

3D Models & How They Were Produced

The three café items, a Croissant, a Cup of Coffee, and a Chocolate Chip Cookie, were each modelled in Blender 5.0 and exported in GLB (GL Binary) format for integration into the web application. I chose GLB because it packages geometry, materials, and PBR textures into a single binary file, making it efficient to load over the web.

Each model was built with the final web rendering in mind, keeping polygon counts reasonable for real-time performance while maintaining enough geometric detail to look convincing when lit. The Chocolate Chip Cookie was the most complex of the three, requiring careful sculpting of the surface irregularities, chocolate chip placement, and the uneven edge profile to give it a realistic baked appearance.

The models are loaded at runtime using Three.js GLTFLoader rather than being embedded in the HTML, which keeps the page lightweight and lets each model load on demand when the user selects it. Each model is automatically centred and scaled in the scene using a Box3 bounding box calculation, so regardless of the original dimensions in Blender, it always displays correctly in the viewport. The models are rendered under a three-point lighting rig consisting of a main directional light simulating overhead café illumination, a warm accent light, and a fill light to give depth and dimension to each object.

Technology Choices & Rationale

I chose Three.js over X3DOM because it felt like the more practical option. It has a much bigger community, the documentation is easier to follow, and it works really well with GLB files which is the format my models were in. Three.js is loaded using an importmap, which is a cleaner way of bringing the library into the page without cluttering the JavaScript.

OrbitControls were something I added early on because I wanted users to actually be able to explore the models freely. Dragging to rotate and scrolling to zoom feels natural and makes the 3D element genuinely interactive rather than just decorative. RGBELoader was used to power the Studio Light button. It loads a real photograph of a Venice sunset sky and uses it to light the entire scene, which makes the models look far more realistic than basic directional lights alone. I applied ACES Filmic tonemapping to the renderer because it makes the colours look warmer and more cinematic, which suited the café aesthetic I was going for. The HTML5 Audio API handles the ambient jazz track and I felt audio really completed the café atmosphere. For the layout I used CSS Grid because it made it straightforward to build the two-column design with the control panel on the left and the 3D viewer taking up the right side.

Interactivity Features

The application includes the following interactive features, all triggered through the user interface:

  • Model selection — clicking a menu item loads the corresponding GLB model and updates the info panel below with the item name, description, ingredients and price.
  • Drag to rotate / scroll to zoom — OrbitControls allow the user to examine each model from any angle.
  • Wireframe toggle — switches the model to wireframe view, revealing the underlying polygon geometry.
  • Lighting controls — two independent light toggles (Main Light and Warm Accent) change how the model is illuminated.
  • Studio Light — loads an HDR environment map for physically accurate image-based lighting.
  • Colour swatches — four colour variants per model let the user change the surface colour in real time, with dark details preserved via luminance thresholding.
  • Animate Spin — triggers a full 360° rotation animation on the model using JavaScript onClick.
  • Café Ambience audio — toggles an ambient jazz café track via the HTML5 Audio API.
  • Content swapping — the Menu and About pages swap without reloading the page, handled via JavaScript show/hide.

Accessibility

Accessibility was something I wanted to take seriously rather than just tick a box. I added aria-label attributes to the main buttons so that someone using a screen reader would hear a clear description of what each element does. The scrolling ticker strip at the top is purely decorative so I marked it as aria-hidden, which means screen readers skip over it completely and do not read out the repeating text. I also added support for the prefers-reduced-motion setting, so if someone has turned on reduced motion in their device settings, the ticker animation automatically pauses. I used proper semantic HTML elements throughout so screen readers can navigate the page structure easily.

Testing

Testing was something I had to work through carefully, especially because of how Three.js loads 3D models. The biggest issue I ran into early on was that when I opened the HTML file directly in the browser by double-clicking it, none of the 3D models would appear and the page just kept showing the loading spinner. After looking into it I found this was a CORS (Cross-Origin Resource Sharing) security restriction that browsers enforce when loading local files. I fixed this by using the Live Server extension in VS Code, which runs a proper local server and allows the GLB files to load correctly.

Safari was another challenge because even with Live Server running, Safari still blocked the models from loading. I switched to Chrome for development which worked without any issues. This is also why the final version hosted on the Sussex ITS server works in all browsers, since it runs over a real web server rather than a local file path. I used Chrome DevTools to check how fast the models were loading and each GLB file came in under 500ms which felt reasonable for a web app. I also tested the layout at different screen sizes to make sure the responsive breakpoint at 900px worked properly, collapsing the two-column layout down to a single column on smaller screens.

One usability improvement I made following tutor feedback was making the Maison Dorée logo in the header clickable, so it takes the user back to the main menu from the About page. This is a common navigation convention and users naturally expect clicking a brand logo to bring them back to the home page, so not having it felt like a gap in the experience. Once I implemented it the navigation felt much more intuitive. I also removed the Reserve and Contact links from the navigation since they had no content behind them, which the tutor pointed out looked unfinished and unnecessary.
